# Roadmap to production

Документ описывает, чего не хватает, чтобы довести текущий прототип до боевого состояния: какие долги оставлены сознательно, какие возможности отсутствуют, какие риски это создаёт и в каком порядке их закрывать.

Стек уже умеет поднять один Linux VPS: PostgreSQL в приватной сети Compose, одноразовая миграция Alembic до старта API, Nginx как единственная опубликованная точка, healthcheck, секреты только в `.env`. Это контур для демонстрации и пилота, не для открытого продакшена.

Пункты 5–8 можно выполнять параллельно с пунктами 3–4 после закрытия всех P0.

## Технические долги, оставленные сознательно

Это не забытые баги. Каждый пункт — принятое ограничение прототипа. Пока оно не закрыто, его нужно считать частью контракта системы.

| Долг | Почему так сейчас | Что нельзя делать «по пути» |
| --- | --- | --- |
| Анонимный workspace-токен вместо пользователей | Страница открывается сразу, без регистрации. В браузере лежит bearer-токен, в PostgreSQL — только его SHA-256 | Не считать токен учётной записью и не шарить одну ссылку «на команду» |
| Календарные дни, включая выходные и праздники | Длительность — включительные календарные сутки. Правило одинаково для Excel, формы и чата | Не менять семантику длительности точечно в UI, не пересчитав импорт, экспорт и агента |
| Ручная форма не подтягивает задачи за предшественниками | Введённые даты сохраняются как есть; конец выводится из начала и длительности. Каскад потомков делает чат, когда меняется расписание | Не «улучшать» форму молчаливым сдвигом: пользователь перестанет понимать, какая дата его |
| Успешный ответ модели применяется сразу | После валидации план коммитится одной транзакцией. Отдельного шага «подтвердить правку» нет; защита — версия, отмена и отказ при ошибке | Не коммитить частичный набор tool call и не оставлять план в промежуточном виде |
| TLS не входит в Compose | Стек публикует только HTTP. Сертификат завершается перед ним: Caddy, Traefik или Nginx хоста | Не выпускать 443 из контейнера приложения «на скорую руку» без сохранения `Host`, `X-Forwarded-*` и upgrade для WebSocket |
| Бэкапы — обязанность оператора | Именованный том `ganttai-postgres` переживает пересоздание контейнеров, но не потерю диска | Не добавлять `-v` к `docker compose down`: это удаляет том |
| Автоповтор последнего сообщения чата снят | Его успели сделать и откатили: повтор после обрыва мог продублировать правку. Остался только реконнект WebSocket | Не возвращать retry без идемпотентного ключа запроса |
| Обход стрелок вокруг коллизий снят | Маршрутизация была и откачена. Остались цвет линий и сглаживание | Не чинить читаемость графа скрытым изменением геометрии без отдельной проверки |
| Зависимости фронтенда в `package.json` записаны как `latest` | Фиксация фактических версий — `package-lock.json` и `npm ci`. Бэкенд зафиксирован хешами в `requirements.lock` | Не обновлять lock командой без ревью диффа |
| Один VPS, PostgreSQL в том же Compose | Так зафиксирован контур поставки. Kubernetes и отдельный управляемый кластер сознательно не вводились | Не раскладывать сервисы по хостам, не поменяв сеть, секреты и процедуру миграции |

Отдельная граница, а не долг: у модели нет публичного MCP-транспорта, shell, файловой системы, прямого SQL и произвольной сети. Инструменты — только `read_plan`, `add_task`, `update_task`, `set_dependencies`, `delete_tasks` внутри процесса API. Это не нужно «открывать для интеграций» в рамках выхода в прод.

## Чего не хватает для продакшена

### Безопасность и деньги на модель

- HTTPS на домене. Сейчас наружу смотрит порт 80. Токен workspace и текст плана уходят открытым текстом, если сервер доступен не только с localhost.
- Лимиты запросов на импорт, экспорт, правку задач и WebSocket-чат. Сейчас границы есть у книги (2 МиБ, 500 строк) и у одного хода модели (таймаут, `OPENROUTER_MAX_OUTPUT_TOKENS`, не больше 30 tool call), но нет лимита на число ходов с одного токена.
- Потолок расходов OpenRouter: дневной или помесячный бюджет, обрыв при превышении, запрет чата при пустом ключе без бесконечных ретраев клиента.
- Отзыв и ротация workspace-токена. Украденный токен из `localStorage` даёт все проекты этого пространства до тех пор, пока база жива.

### Наблюдаемость и данные

- Структурные логи без промптов, ключей и сырых ответов провайдера. Сейчас диагностика — `docker compose logs`.
- Алерты на упавшую миграцию, неготовый `/health/ready`, рост ошибок чата и недоступность PostgreSQL.
- Автоматический `pg_dump` вне VPS и регулярная проверка, что дамп действительно восстанавливается. Команды восстановления есть, расписания и чужого хранилища нет.
- Политика хранения версий плана. Версии иммутабельны и полезны для отмены, но роста таблицы `plan_versions` никто не ограничивает.

### Поставка и доступ

- CI: backend-тесты, frontend-тесты, `npm run build`, `docker compose config --quiet` на каждый push. Сейчас это ручные команды. Каталога `.github` нет.
- CD с тем же порядком, что у ручного обновления: бэкап, сборка, миграция до приёма трафика, smoke-test, отказ оставлять API запущенным после сломанной миграции.
- Пользователи, сессии и роли. Сейчас любой, у кого есть токен, может читать, менять, экспортировать и удалять проекты пространства. Нет приглашений, нет разделения «смотрит / редактирует / администрирует».
- Согласие на обработку текста плана сторонней моделью. План и реплики уходят в OpenRouter. Для боя это нужно сказать пользователю до первого сообщения чата и уметь работать с диаграммой и Excel без модели.

### Интерфейс, без которого пилот ещё терпим, а продукт — нет

- Адаптивная вёрстка. На узком экране уже есть переключатель «План / ИИ-ассистент», но это не законченный мобильный сценарий импорта, чата и шкалы.
- Календарь диаграммы: читаемость шкалы, навигация по длинному плану, понятные границы недель. Семантику «день = календарные сутки» этот пункт не меняет.
- Быстрые ответы в чате и голосовой ввод — удобство, не контур безопасности. Их нет в коде.

## Риски, если выйти как есть

| Риск | Что происходит | Чем уже смягчено | Почему этого мало |
| --- | --- | --- | --- |
| Открытый HTTP | Токен и план читаются на пути | В проде опубликован только Nginx; Postgres и API без портов хоста | Нет шифрования и привязки к домену |
| Счёт OpenRouter | Публичный или утёкший токен крутит чат, пока ключ жив | Таймаут, лимит токенов ответа, потолок tool call, ключ не в браузере | Нет квоты на workspace и аварийного выключателя |
| Кража токена | Полный доступ к проектам, чату и экспорту | В базе хранится хеш, не сам токен; WebSocket не кладёт токен в URL | Нет ролей, отзыва и срока жизни. XSS страницы равен компрометации пространства |
| Потеря тома или диска | Проекты и история невосстановимы | Том именованный; ручной `pg_dump` описан | Нет расписания, чужого хранилища и учебной реставрации |
| Тихий отказ | Миграция не прошла или API не готов, а это заметно только человеку у сервера | API не стартует, пока `alembic upgrade head` не успешен; есть `/health/live` и `/health/ready` | Нет алерта и дежурства |
| Правка «не той» задачи | Модель проходит валидацию и записывает не то, что имел в виду человек | Циклы, чужие имена и лимиты отвергаются; старая версия остаётся; есть «Отменить» | Нет шага подтверждения. Отмена помогает, только если её заметили |
| Обновление зависимостей | `npm install` без lock или бездумный bump тянет новый фронтенд | Образы собираются через `npm ci` и хешированный Python lock; базовые образы закреплены digest | В `package.json` стоит `latest`. Это ловушка при следующем обновлении |
| Чужой текст в провайдере | Описание задач и переписка покидают контур | Ключ и сырой ответ провайдера не пишутся в браузер и не отдаются в WebSocket | Нет договора, ретеншена и режима «чат выключен» для чувствительных планов |

Остаточный продуктовый риск, не баг валидации: агент может задать уточнение и ничего не изменить. Это безопасный путь. Опасный путь — уверенная, но неверная правка, которая формально валидна.

## Порядок закрытия

Не начинать P1, пока не закрыты оба P0. Иначе CI будет выкатывать тот же открытый HTTP, а роли не защитят ключ модели.

1. **P0. HTTPS, лимиты запросов и защита от перерасхода OpenRouter.** Домен, TLS перед стеком, `wss` на том же origin, лимит на IP и на workspace, бюджет модели и внятная ошибка вместо молчаливого списания. Готово, когда чат и импорт недоступны при превышении бюджета, а по HTTP снаружи больше нет плана.
2. **P0. Логи, алерты, автоматические бэкапы и проверка восстановления.** Логи без секретов, алерт на migrate/ready, ежедневный дамп вне сервера, один успешный restore на чистый том по расписанию, которое реально выполняли. Готово, когда восстановление проверено не инструкцией, а прогоном.
3. **P1. CI/CD.** Те же проверки, что в разделе «Проверка» README, плюс сборка образов. Выкладка не обходит миграцию и не стартует API после её падения.
4. **P1. Пользователи, сессии и роли.** Учётка вместо бессрочного анонимного токена, отзыв сессии, минимум две роли. Старые workspace не должны внезапно стать общими.
5. **P1. Адаптивная вёрстка.** Импорт, чат, таблица и шкала проходят основной сценарий на узкой ширине без потери черновика и без горизонтального разъезда действий.
6. **P1. Отображение календаря.** Шкала читается на длинном плане; изменение не переопределяет правило календарного дня.
7. **P2. Быстрые ответы в чате.** Короткие команды не обходят валидацию и версию плана.
8. **P2. Голосовой ввод.** Текст перед отправкой виден и редактируется; аудио не уходит в API плана отдельным непроверенным каналом.

Пункты 5–8 не блокируют друг друга и могут идти параллельно с 3–4 после P0. Пункты 7–8 не являются условием первого боевого включения, если чат текстом уже пригоден.

## Когда можно считать контур боевым

Минимальный порог — закрытые P0 и работающий откат:

- домен и HTTPS, WebSocket чата на `wss`;
- лимит запросов и потолок OpenRouter проверены отказом, а не оценкой;
- свежий дамп восстановлен на чистый том, проект и чат читаются;
- алерт приходит, если миграция или `/health/ready` падают;
- секреты не в git, не в образе и не в логах;
- человек может отменить последнюю версию плана.

Пользователи и роли нужны до любой передачи доступа незнакомым людям. Адаптив, календарь, быстрые ответы и голос на этот порог не влияют.
